# 学习路径设计（第 11 章的做法）

原则：路径的终点是"能独立交付一个需求"，不是"看完了所有目录"。每一阶段都要有**能被验收的产出**，否则学习者无法判断自己过没过关。

## 四阶段框架

### 阶段一：跑起来（半天）
目标：本地能访问，能改一行字并看到变化。
任务：装依赖、配环境变量、启动、找到首页对应的文件、改一句文案确认热更新生效。
验收：截图或说出改动前后的差异，并说清这行文案在哪个文件第几行。
常见卡点要预先写出来（Node 版本、环境变量缺失、端口占用、依赖源）。

### 阶段二：读懂一条链路（1-2 天）
目标：讲清一个真实功能从点击到落库的全过程。
任务：照着第 7 章的链路自己走一遍，然后**换一个功能**独立追一遍，画出分层链路表。
验收：能回答三个问题——鉴权在哪一步做的、失败时用户看到什么、数据写进了哪几张表。

### 阶段三：改一个小功能（2-3 天）
目标：在既有链路上加东西，不破坏现有行为。
任务选题标准：跨至少两层（前端 + 服务端或数据库）、有明确验收标准、不碰核心计费或权限。例如给某个列表加一个筛选项、给某个表单加一个字段并存库、给某个页面加一个状态提示。
验收：改动符合仓库既有写法（第 8 章的规范）、通过 lint 与类型检查、自测路径写清楚、提交信息符合项目风格。

### 阶段四：独立做一个需求（1 周）
目标：从需求到上线全流程走通。
任务：一个完整小功能，含数据模型改动、前后端、权限、错误处理。
验收：自己先按第 10 章的坑位清单自查；能说清这次改动影响了哪些既有功能；能写出这个功能的讲解（反过来教别人，是掌握的最好证明）。

## 按角色裁剪

| 听众 | 调整 |
|---|---|
| 零基础学员 | 阶段一拆成三步（装环境 / 跑起来 / 改一行），阶段二只追半条链路（前端到接口），阶段三改纯前端 |
| 会写代码不熟这个栈 | 阶段一压缩成两小时，重点放在"这个栈的惯用法与你熟悉的栈有什么不同"，阶段二直接追最复杂的那条链路 |
| 资深工程师接手 | 跳过阶段一二的练习，直接给：架构决策清单、技术债地图、坑位清单、近半年热点文件，路径改成"第一周该重构什么/先别动什么" |
| 只做前端 / 只做后端 | 另一侧只讲接口契约与数据形状，不展开内部实现，但**权限与数据校验在哪一层**必须讲 |

## 出练习题的规矩

- 指名到文件：写"在 `[src/pages/X.tsx](src/pages/X.tsx)` 里加一个筛选下拉"，不写"熟悉页面结构"。
- 给验收标准：改完之后应该看到什么、怎么自测。
- 给参考样例：仓库里已有的同类实现指一个，让学习者照着写。
- 给逃生通道：卡住超过 X 时间该去看哪个文件或问什么问题。
- 难度递增且互相衔接：后一题建立在前一题的产出上。

## 时间估算

给区间不给定值（"半天到一天"），并说明估算基于哪种水平。仓库特别大或环境特别难配时，如实说明阶段一可能就要一天。
