# AI 协作配置解读（第 9 章的做法）

现在的仓库里，`CLAUDE.md`、`AGENTS.md`、`.claude/` 往往比 README 更接近真相——它们是团队反复踩坑后写下的"给 AI 也是给人的施工须知"。新人读懂这些，等于拿到了前人的教训清单。

## 先盘清楚有哪些

`repo_scan.sh` 第 6 节已经列出来了。常见的有：

| 文件 / 目录 | 是什么 | 谁在读 |
|---|---|---|
| `CLAUDE.md` | 项目级指令，Claude Code 每次会话自动加载 | Claude Code |
| 子目录里的 `CLAUDE.md` | 只对该目录生效的局部规则 | Claude Code |
| `AGENTS.md` | 跨工具的通用 agent 指令（Codex 等在读） | 多家工具 |
| `GEMINI.md` / `.cursorrules` / `.windsurfrules` / `.github/copilot-instructions.md` | 各家工具的同类文件 | 对应工具 |
| `.claude/skills/<name>/SKILL.md` | 项目自带技能：把一套固定流程封装成可调用的能力 | Claude Code |
| `.claude/agents/*.md` | 子代理定义：特定任务派给特定人格与工具集 | Claude Code |
| `.claude/commands/*.md` | 斜杠命令：可复用的提示词模板 | Claude Code |
| `.claude/settings.json` / `settings.local.json` | 权限允许列表、环境变量、hooks | Claude Code |
| `.mcp.json` | 外部工具服务（数据库、云平台、文档）接入配置 | MCP 客户端 |

多份文件并存时要说清**谁覆盖谁**：一般是"全局用户配置 → 项目 CLAUDE.md → 子目录 CLAUDE.md"逐级细化，越近越优先；`settings.local.json` 是个人本地覆盖，通常不进版本库。

## 怎么讲每一条规则：翻译成"在防什么坑"

逐条复述规则没有价值，要做三件事：

1. **归类**：把散落的条目归到几类——安全红线（禁删 .env、禁写生产库）、流程约定（提交格式、部署命令）、架构约束（新功能必须走某个组件）、踩坑记录（改 A 必须同步改 B）、风格偏好（回复语言、文档位置）。
2. **还原动机**：这条规则在防什么事故。能从 `git log` 找到那次事故的提交就贴出来，这是最有说服力的讲法。找不到就写"未见记载，推测是为了 X"，并标明是推测。
3. **给出执行动作**：这条规则落到日常操作上是什么。例如"改了模型清单要同步改定价卡片"，就直接列出两个文件的链接，说明改动顺序。

输出成表：

| 规则 | 类别 | 在防什么 | 你该怎么做 |
|---|---|---|---|

## 重点看这几类高价值条目

- **"改 X 必须同步改 Y"** 的联动清单：这是仓库里最难自己发现的知识，必须原样保留并核实文件是否还存在。
- **命名与真值不一致的约定**：例如展示名与数据库存储值不同、某个字段名与含义相反。这类条目直接进第 12 章术语表。
- **禁止事项**：尤其涉及生产数据、密钥、部署的，原样保留，不要因为看起来啰嗦就精简。
- **部署与环境命令**：确认命令在 `package.json`/CI 里仍然有效。

## 核实规则是否已过期

逐条抽查（方法见 `recon-playbook.md` 第 6 节）。结果分三档并在手册里标注：

- **现行有效**：代码与规则一致。
- **已漂移**：代码里存在 N 处例外，给出例子，提醒接手者先问团队。
- **已失效**：规则提到的文件、命令、字段已经不存在。这类要单独列一张"建议清理"的小表，交给用户决定是否更新配置文件。

这张漂移表往往是本次讲解里最有实用价值的产物。

## 讲项目自带的技能与子代理

对 `.claude/skills/` 下的每个技能，讲三句：什么时候会被触发（读 frontmatter 的 description）、它替人做了哪几步、产物落到哪。对 `.claude/agents/` 同理，额外说明它被限制了哪些工具。

对 `.mcp.json`：只讲接入了哪些外部服务、各自能做什么、有什么风险（例如能直连生产数据库的，要提醒写操作前必须确认）。**不要回显配置里的 token 或 access key**，只说"凭据写在配置里，注意不要提交到公开仓库"。

## 如果仓库里什么都没有

也是有价值的一章：说明这个项目还没有 AI 协作约定，并给出一份**建议放进 CLAUDE.md 的初始条目清单**——从本次讲解中发现的坑位、联动关系、部署命令里提炼 5-10 条。这是代码教练能顺手留下的最实在的东西。
