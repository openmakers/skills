# 科普脚本写法

## 三种选题，三套骨架

| 选题 | 例子 | 场景顺序 | 时长 |
|---|---|---|---|
| **概念课**：讲清一个词 | 什么是 Skill / MCP / Agent / RAG / 上下文窗口 | hook → term → metaphor → compare → layers 或 steps（它怎么工作）→ chat 或 terminal（用起来什么样）→ tools（哪里能用）→ list（上手要点）→ quote → outro | 90–150 秒 |
| **方法课**：教一套做法 | 怎么写好提示词 / 怎么让 AI 帮你做周报 | hook → compare（常见做法 vs 更好的做法）→ steps（三到四步）→ chat（示范一次）→ list（避坑）→ quote → outro | 60–120 秒 |
| **工具盘点**：推荐一批工具 | 五个免费的 AI 写作工具 | hook → tools（总览）→ 每个工具一场 term 或 image（它能干什么）→ compare（怎么选）→ outro | 60–120 秒 |

短视频平台（竖屏）控制在 60 秒内：概念课砍掉 compare 与 tools，只留 hook → term → metaphor → steps → quote → outro。

## 旁白

- **口语、短句**：一句 12–25 字，读出来 3–5 秒。长句用逗号断开，字幕会在逗号处自动切条。
- **先打比方，再给定义**：观众先听懂「像什么」，再记住「是什么」。
- **一场一个意思**，场内 2–4 句。第一句常是铺垫（`beat: false`），后面每句带出一个画面元素。
- **旁白讲道理，画面给关键词**：画面写「按需加载」，旁白说「平时只记住名字，遇到对口的任务才翻开」。
- **说人话**：避免「赋能」「范式」「底层逻辑」；术语第一次出现时顺手解释（「上下文，就是 AI 这一轮能看到的全部内容」）。
- **不替观众表态**：不写「你一定会爱上它」「相信你已经懂了」。
- **数字**：画面和字幕写阿拉伯数字；读法不确定的写 `read`（年份、版本号、带小数点的数、英文缩写）。
- **英文术语**：`Skill`、`Claude`、`Codex`、`Cursor`、`AI` 直接写，MiniMax 能读；文件名、路径写 `read`（`SKILL.md` → `SKILL 点 MD`）。
- 语速：`presenter_female` 语速 1.05 约 4.5–5 字/秒。130 秒的片子，旁白约 500 字。

## 画面文字

- **标题名词化**：场景标题、卡片标题、步骤名都是名词或名词短语，不写问句和口号句。
- 标题 12 字以内；卡片说明 16 字以内；要点每条 12 字以内。
- 一个画面最多一处马克笔高亮 `**…**`，高亮最关键的那个词。
- 不放 emoji，不放装饰图标；需要状态就写字（已支持 / 最早推出）。
- 页面上不出现具体技能的英文 ID（例：写「科普视频」这个 Skill，不写 ai-concept-video）；通用概念词（Skill、MCP、Agent、CLI）可以用。

## 查证清单

写进脚本之前，每一条都要有出处：

| 类型 | 查哪里 |
|---|---|
| 发布时间、出品方 | 官方博客、官方文档、新闻稿 |
| 支持哪些工具 / 平台 | 官方文档的集成列表，或各工具自己的文档 |
| 价格、免费额度 | 官网定价页（写明「截至 X 年 X 月」） |
| 数字（用户数、模型参数、排名） | 原始出处；二手转述的不用 |

查不到或说法不一的，要么不写，要么换成不需要数字的说法（「很多工具都已支持」）。出处记进项目 README 的「来源」一节。

## 样片旁白（什么是 Skill，约 500 字）

见 `template/script.js`。可以照它的节奏改写成别的概念：MCP（类比：USB 接口）、Agent（类比：会自己跑腿的助理）、RAG（类比：开卷考试）、上下文窗口（类比：工作台桌面的大小）。
